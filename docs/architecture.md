# Architecture

## Overview

**bitwarden-desktop-native** is a lightweight Rust alternative to the official Bitwarden desktop app (Electron/Angular). It uses the **Iced 0.14** GUI framework with an Elm-style architecture.

## Tech Stack

- **Language**: Rust (2024 edition)
- **GUI**: Iced 0.14 (wgpu/tiny-skia rendering, no webview)
- **Menus**: `muda` for native macOS menu bar; custom-drawn iced widget on Windows/Linux
- **Icons**: Bootstrap Icons v1.13.1 (TTF font, codepoints auto-generated by `build.rs`) + Bitwarden Icons (bwi) font for sidebar/detail pane
- **Font**: Inter (variable, bundled in `assets/InterVariable.ttf`)
- **Architecture**: Elm pattern — `Message` enums drive state transitions via `update()`, `view()` renders UI from state

## State Model

```rust
struct AppState {
    users: HashMap<UserId, UserSession>,  // Mirrors future SDK HashMap<UserId, PasswordManagerClient>
    active_user: Option<UserId>,
    screen: Screen,  // Login | Vault
}

struct UserSession {
    email: String,
    display_name: String,
    server_url: String,      // e.g. "bitwarden.com"
    locked: bool,
    vault_items: Vec<CipherItem>,
}

struct CipherItem {
    id: String,              // Stable identifier for selection tracking
    name: String,
    username: Option<String>,
    url: Option<String>,
    category: CipherCategory,
}
```

The app holds multiple user sessions simultaneously. Switching to a locked user navigates to the unlock screen; switching to an unlocked user shows their vault.

### Selection Model

Item selection uses a stable ID (`selected_id: Option<String>`) rather than a list index. This allows the detail pane to stay open when the filtered list changes (e.g. during search). The `selected_item: Option<usize>` index is re-synced from the ID after each filter/cache refresh for list highlighting.

### PaneGrid State

The vault view uses `pane_grid::State<PaneKind>` for a resizable two-pane split:
- `PaneKind::List` — item list with header, search, and scrollable items
- `PaneKind::Detail` — detail pane showing the selected item
- Split ratio persists across re-renders; min pane size: 250px
- When no item is selected, the list fills the full width (no PaneGrid)

## Message Flow

```
App::new() → (State, Task::none())
  ↓
Subscription: listen for Window::Opened event
  ↓
WindowOpened(id) → raw_id(id) Task
  ↓
GotRawId(hwnd) → menu::attach_menu(hwnd) (macOS: native menu, Windows/Linux: no-op)
  ↓
User interaction → Login/Vault/MenuBar messages → update() → view()
  ↓
Search input → focus task returned to maintain text input focus across PaneGrid rebuilds
  ↓
DEV_SCREENSHOT env set? → screenshot Task → save PNG → exit
```

## Menu System

### Architecture
The menu is defined once in `menu.rs` as a const data structure (`MENUS`) and consumed by two backends:
- **macOS**: `muda` crate builds native NSMenu items from the same data, attached via `init_for_nsapp()`
- **Windows/Linux**: `widgets/title_bar.rs` renders the menu as iced widgets inside the window

### Why not native menus on Windows?
Native Win32 menus (via `muda::init_for_hwnd()`) create a 1px transparent gap between the menu bar and the iced client area. This is a known issue — the DWM compositor draws a border that can't be controlled from iced. Drawing the menu ourselves eliminates this.

### Menu Data Model
```rust
enum MenuEntry {
    Item { label, shortcut: Option<Shortcut>, enabled: EnabledWhen },
    Separator,
    SubMenu { label, items: &[MenuEntry], enabled: EnabledWhen },
}

enum EnabledWhen { Always, Unlocked, HasAccounts, HasLockable, HasAuthenticated }

struct MenuState { is_locked, has_accounts, has_lockable_accounts, has_authenticated_accounts }
```

Each item has a `Shortcut` with platform-specific strings (`win`/`mac`). Linux uses the same shortcuts as Windows (Ctrl+). `EnabledWhen` is evaluated against `MenuState` at render time.

## Icon System

### Bootstrap Icons
- Font file: `assets/bootstrap-icons-1.13.1.ttf` (converted from WOFF)
- CSS file: `assets/bootstrap-icons-1.13.1.css` (contains icon name → Unicode codepoint mappings)
- `build.rs` parses the CSS and generates `bootstrap_icons_generated.rs` with:
  - `FONT_BYTES: &[u8]` — the font data (included via `include_bytes!`)
  - `const SEARCH: Icon = Icon('\u{f52a}')` — one constant per icon (~2078 total)

### Bitwarden Icons (BWI)
- Font file: `assets/bwi-font.ttf` (copied from `clients/libs/angular/src/scss/bwicons/fonts/`)
- Codepoints defined manually in `src/icons.rs` from `clients/libs/angular/src/scss/bwicons/styles/style.scss`
- `BWI_FONT_BYTES: &[u8]` loaded in `main.rs` via `.font()`
- Used in sidebar and detail pane for matching the official app's icon set

### Icon Types
```rust
struct Icon(char);       // Bootstrap Icons, renders with FONT
struct BwiIcon(char);    // Bitwarden Icons, renders with BWI_FONT

impl Icon/BwiIcon {
    fn render(&self, size: f32, color: Color) -> Element<M> { ... }
}
```

Usage: `icons::SEARCH.render(14.0, theme::TEXT_MUTED)` or `icons::BWI_VAULT.render(18.0, theme::TEXT_PRIMARY)`

## Shared UI Helpers (`widgets/common.rs`)

Reusable helpers to reduce duplication across widgets:

```rust
fn separator_h() -> Element<M>     // Horizontal rule with BORDER color
fn separator_v() -> Element<M>     // Vertical rule with BORDER color
fn hover_button_style(status, is_active, active_bg, radius) -> button::Style
fn styled_card(content) -> Element<M>  // Card with BACKGROUND bg, RADIUS_LG corners
```

## Theme System (`theme.rs`)

Colors are module-level constants. Some share the same hex value for different semantic purposes:
- `HEADER_BG` == `BORDER` (#303946) — sidebar/titlebar bg vs separator color
- `CARD_BG` == `SIDEBAR_SELECTED` (#121a27) — detail pane bg vs sidebar active item
- `TEXT_MUTED` == `TABLE_HEADER` (#8898b5) — label text vs column header text

Radius constants: `RADIUS_SM` (4), `RADIUS_MD` (6), `RADIUS_LG` (8), `RADIUS_PILL` (20).

## Overlay Pattern

Iced doesn't have native popover/overlay support. We use `iced::widget::stack!` to layer floating elements (dropdowns, menus) on top of the page content:

```rust
if let Some(dropdown) = menu_bar::dropdown(...) {
    let overlay = column![Space::height(28.0), dropdown];
    stack![content, overlay].into()
} else {
    content.into()
}
```

This pattern is used for:
- **Account switcher dropdown** — floating below the trigger button
- **Menu dropdowns** — floating below the menu bar
- **Menu submenus** — floating beside the parent dropdown

## Screenshots

Screenshots use iced's built-in `window::screenshot()` API:
- Set `DEV_SCREENSHOT=path.png` env var before launching
- The app captures a screenshot on first render via `Window::Opened` subscription and exits
- `screenshot-all.ps1` automates capturing both login and vault screens

## Future SDK Integration

The business logic will come from a separate Rust SDK centered around `PasswordManagerClient`:

```rust
let client = LoginClient::new().login_with_password(params).await?;
let client = PasswordManagerClient::load_from_state(params).await?;
client.unlock().unlock_with_password(pw).await?;
let ciphers = client.vault().ciphers().list().await?;
```

The current stub uses mock data. The state model (`HashMap<UserId, UserSession>`) mirrors the SDK's `HashMap<UserId, PasswordManagerClient>` for straightforward integration.

## Build Configuration

### Release Profile
```toml
[profile.release]
lto = true           # Full link-time optimization
codegen-units = 1    # Single thread for better optimization
strip = true         # Strip debug symbols
opt-level = "s"      # Optimize for size
panic = "abort"      # No unwinding overhead
```

### Windows Subsystem
`#![cfg_attr(not(debug_assertions), windows_subsystem = "windows")]` hides the console window in release builds.

## Key Dependencies

- `iced = "0.14"` with `tokio` and `svg` features — GUI framework
- `muda = "0.17"` — Native OS menus (macOS only at runtime)
- `png = "0.17"` — Screenshot encoding
