# Architecture

## Overview

**bitwarden-desktop-next** is a lightweight Rust alternative to the official Bitwarden desktop app (Electron/Angular). It uses the **Iced 0.14** GUI framework with an Elm-style architecture.

## Workspace Structure

The project is a Cargo workspace. The root `Cargo.toml` defines:

- `crates/desktop` — main desktop application (default member)
- `bitwarden_license/*` — licensed workspace members (future)
- `tools/*` — developer tools:
  - `tools/packager` wraps `cargo-packager`
  - `tools/fake-data` one-shot generator that calls the real Bitwarden SDK to produce `assets/mock-vault.json` (encrypted ciphers + user keys) for dev-mode unlock

`default-members` is `crates/*`, `bitwarden_license/*`, so `cargo run` targets the desktop app. `cargo run -p fake-data` runs the generator; `cargo run --bin packager` runs the packager.

Shared dependencies (`serde`, `serde_json`, `async-trait`, `tokio`, `bitwarden-*` git pins) are defined under `[workspace.dependencies]` in the root `Cargo.toml` and consumed via `{ workspace = true }` so every member tracks the same version and bitwarden SDK revision.

## Tech Stack

- **Language**: Rust (2024 edition)
- **GUI**: Iced 0.14 (wgpu/tiny-skia rendering, no webview) with `tokio`, `svg`, `advanced`, `image` features
- **SDK**: `bitwarden-core` / `bitwarden-crypto` / `bitwarden-pm` / `bitwarden-state` / `bitwarden-vault` git-pinned to a specific revision. Handles all real crypto: `make_register_keys`, `initialize_user_crypto`, `ciphers().encrypt/decrypt/decrypt_list`, `folders().encrypt/decrypt_list`
- **Menus**: `muda` for native macOS menu bar + optional on Windows/Linux via `DEV_BOTH_MENUS=1`; custom-drawn iced title bar on Windows/Linux
- **Icons**: Bootstrap Icons v1.13.1 (TTF font, codepoints auto-generated by `build.rs`) + Bitwarden Icons (bwi) font
- **Font**: Inter 18pt static — `Inter_18pt-Medium.ttf` (default, weight 500) + `Inter_18pt-Bold.ttf`. Family name: `"Inter 18pt"`. Constants: `APP_FONT` / `APP_FONT_BOLD` in `main.rs`.
- **Theme**: Custom `AppTheme` type with dark/light palettes, runtime switching. Light is the default theme.
- **Architecture**: Elm pattern — view structs own state, `update()` returns action enums for cross-cutting effects
- **Packaging**: `cargo-packager` via `Packager.toml` for .app/.dmg/.msi bundles

## State Model

```rust
// Root app — thin dispatcher (~18 fields)
struct App {
    state: AppState,                         // users HashMap + active_user + screen
    theme_preference: ThemePreference,
    current_theme: AppTheme,
    login_view: LoginView,
    vault_view: VaultView,
    title_bar: TitleBarState,
    client_manager: Arc<ClientManager>,      // per-user PasswordManagerClient + crypto inputs
    toasts: Vec<Toast>,                      // overlay queue, pushed via App::push_toast
    system_theme: Arc<SystemTheme>,
    native_menu: Option<NativeMenuHandle>,
    // + cached_email/server/accounts/unlock_alternatives, fullscreen, maximized,
    //   menu_attached, window_id
}

// Each view owns its state and handles its own messages
struct LoginView { password_input, pin_input, show_password, dropdown_open, auth_page, ... }
struct VaultView {
    search_query, active_filter, selected_item, selected_id: Option<CipherId>,
    selected_detail: Option<CipherView>,     // lazily fetched via full_cipher()
    all_items: Vec<Arc<CipherListView>>,     // SDK types; Arc because CipherListView is not Clone
    cached_items: Vec<Arc<CipherListView>>,  // filter + search applied
    sidebar_*, pane_state, ...
}
struct TitleBarState { open_menu, open_submenu }

// UserSession no longer owns vault data — `ClientManager` does.
struct UserSession { email, display_name, server_url, locked, unlock_methods }
```

### SDK Integration

- `sdk.rs::ClientManager::load()` parses `assets/mock-vault.json` (committed by `tools/fake-data`) at startup, builds one `PasswordManagerClient` per user, and pre-populates each client's `MemoryRepo<Cipher>` and `MemoryRepo<Folder>` with the encrypted ciphers from the JSON.
- `ClientManager::unlock(uid, password)` awaits `crypto().initialize_user_crypto(...)` — real master-password KDF, real user-key unwrap, real keystore populated.
- `ClientManager::list_ciphers(uid)` → `decrypt_list` over the repo. `full_cipher(uid, id)` → `decrypt` on a single `Cipher`. Both are async and wrapped in `iced::Task::perform` from `App::update`.
- Vault data flows as SDK types end-to-end: `item_list.rs` reads `CipherListView.subtitle`, `detail_pane.rs` branches on `CipherView.r#type` and renders per-type cards (Login/Card/Identity/SecureNote/SshKey).

### Action Pattern

Views return action enums from `update()` for cross-cutting effects:
- `LoginAction::Unlock(password)` / `UnlockWithPin` / `UnlockWithBiometrics` / `LogOut` / `SwitchUser(uid)` / `Login { email, password }` / `NavigateToAddAccount`
- `VaultAction::SwitchUser(uid)` / `FocusSearch` / `AddAccount` / `LoadDetail(CipherId)` / `ClearDetail`
- `TitleBarAction::MenuAction(action)` / `Minimize` / `Maximize` / `Close` / `Drag` / `ResizeEdge`

App processes these actions and often translates them to async `Task::perform` work (unlock, list, full_cipher) that lands back as `Message::UnlockCompleted` / `VaultListLoaded` / `CipherDetailLoaded`.

## Menu System

Single `MENUS` static drives both custom and native menus:
- **Custom title bar** (Windows/Linux): renders labels, dropdowns, shortcuts, submenus
- **Native muda** (macOS, or `DEV_BOTH_MENUS=1`): `Shortcut::to_accelerator()` adds shortcuts, `NativeMenuHandle` bridges events via `MenuEvent::receiver()`, `sync_native_enabled()` syncs enabled states

## Icon System

- `Icon(char)` / `BwiIcon(char)` — typed wrappers around font codepoints
- `.render(size, color)` → `Element` for general use
- `.input_icon(size, side)` → `text_input::Icon` for TextInput
- Bootstrap Icons auto-generated from CSS by `build.rs`
- BWI codepoints defined manually from official SCSS

## Overlay Pattern

Two kinds of overlays, both via iced's native overlay system (window-level rendering, not nested in the page layout):

- **Dropdowns** — `components::drop_down::DropDown` (local fork of iced_aw). Custom alignments: `BelowLeft`, `BelowRight`, `AboveRight`. Used for the account switcher and title-bar menus.
- **Toasts** — `components::toast::Manager` wraps the entire app content and overlays a vertical stack of toasts in the lower-right. Animation state (fade in/out, countdown progress, hover-pause) is driven from the overlay's `update()` via `window::Event::RedrawRequested` ticks — no separate `Subscription`. Per-frame opacity/progress values live in `Vec<Rc<Cell<ToastVisuals>>>` on `Manager`, read by the row's style closures at draw time.

## Key Dependencies

- `iced = "0.14"` with `tokio`, `svg`, `advanced`, `image` features
- `muda = "0.17"` — Native OS menus
- `image = "0.25"` — Window icon loading from PNG
- `iced_aw = "0.13"` (default-features = false) — kept as source reference for our `DropDown` fork
- `system-theme` — OS dark/light detection
- `serde` / `serde_json` — `assets/mock-vault.json` deserialization
- `async-trait` — `MemoryRepo` implements `bitwarden_state::Repository` which is async-trait
- `bitwarden-core` / `bitwarden-crypto` / `bitwarden-pm` / `bitwarden-state` / `bitwarden-vault` — SDK (git-pinned revision, shared via `[workspace.dependencies]`)
- `cargo-packager` — used by `tools/packager` for distribution packaging
- In `tools/fake-data` only: `tokio` (rt-multi-thread), `chrono`, `uuid` — driving the async `initialize_user_crypto` call and stamping ciphers
